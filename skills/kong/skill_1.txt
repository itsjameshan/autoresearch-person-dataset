## 1. 核心原则

### 1.1 AI 对话的底层逻辑

AI 本质是一个**基于上下文的概率预测系统**，它根据你提供的输入和之前的对话历史来生成最可能的输出。**输入质量直接决定输出质量**。

**关键认知**：
- AI 不会读心术，**你明确表达的越多，得到的结果越精准**
- AI 有上下文窗口限制，**长对话需定期总结或分段**
- AI 会“迎合”你，如果它不确定，可能会编造答案（幻觉），**关键事实需验证**

### 1.2 高效提问三要素

| 要素 | 说明 | 反面示例 |
|------|------|----------|
| **明确目标** | 说清楚你要什么 | “帮我写个代码” |
| **提供上下文** | 背景、环境、已尝试的方案 | “它报错了” |
| **指定格式** | 期望的输出结构 | 无格式要求 |

**✅ 正确示例**：
> 我在 Python 3.13 环境下运行 Flask 应用，报错 `No module named 'flask'`，请给出安装命令。

**❌ 错误示例**：
> Flask 怎么用？

## 2. 提示词基础框架

### 2.1 万能公式

```
[角色设定] + [背景信息] + [具体需求] + [约束条件] + [输出格式] + [参考示例]
```

### 2.2 实战拆解

**原始需求**：
> 帮我写个网页

**优化后**：
```
你是一名资深前端开发工程师。
我需要在现有的 Flask 项目中修改 index.html，添加一个"批量处理工作流"按钮。
要求：
1. 按钮放在侧边栏底部，绿色背景，圆角
2. 点击后跳转到 /crop 路由
3. 样式与现有按钮保持统一
请给出修改后的完整 HTML 代码。
```

### 2.3 各组成部分说明

| 组成部分 | 作用 | 何时需要 |
|----------|------|----------|
| **角色** | 设定AI的专业领域和语气 | 需要专业建议时 |
| **背景** | 提供环境和前置信息 | 复杂项目或多轮对话 |
| **需求** | 核心任务描述 | 每次都必需 |
| **约束** | 限制范围、格式、长度 | 需要精确输出时 |
| **输出格式** | 指定表格、JSON、代码块等 | 需要结构化结果时 |
| **参考示例** | 提供期望结果的样例 | 风格要求严格时 |

## 3. 结构化提问技巧

### 3.1 拆分问题

**核心思想**：将复杂需求拆解为多个独立的小步骤。

**示例**：
```
❌ 一次性：帮我做一个完整的图片识别系统
✅ 分步骤：
   第1步：先写后端API接收图片
   第2步：再写前端上传界面
   第3步：集成识别模型
   每步确认无误后再进行下一步
```

**实用话术**：
> 请先完成[第一步]，确认后我再让你继续下一步。

### 3.2 限定范围

```
✅ "只修改函数 X，不要动其他地方"
✅ "用 Flask 而不是 Django"
✅ "只用 HTML+CSS，不要引入 JS 框架"
✅ "这个问题的答案请控制在 200 字以内"
```

### 3.3 指定格式

```
✅ "用 Markdown 表格列出"
✅ "请用 JSON 格式返回"
✅ "代码块语言标注为 python"
✅ "分1、2、3点回答"
```

### 3.4 设定身份

```
✅ "你是一名 YOLO 模型训练专家"
✅ "假设你是一个10年经验的前端架构师"
✅ "以初中生能理解的语言解释"
```

## 4. 优化迭代技巧

### 4.1 追问修正

| 问题类型 | 话术模板 |
|----------|----------|
| **没理解需求** | “你可能误解了，我的意思是[重述]” |
| **输出不准确** | “第X点不对，正确的是[修正]” |
| **缺失信息** | “你还漏掉了[补充内容]” |
| **风格不符** | “太啰嗦了，精简到原来的一半” |

### 4.2 补充上下文

**关键**：当回答有问题时，提供**具体错误信息**而非模糊描述。

```
❌ "代码报错了"
✅ "运行后报错：TypeError: 'NoneType' object is not subscriptable，在第45行"
✅ "此处附上完整报错日志：```[日志内容]```"
```

### 4.3 分段输出控制

```
✅ "先列出大纲，我确认后再展开"
✅ "只写第一步的代码，后面的先别写"
✅ "这个函数太长了，拆成三个小函数分别输出"
```

### 4.4 精简/扩写控制

```
✅ "把这段代码精简到 10 行以内"
✅ "给第3点加上一个具体案例说明"
✅ "把技术术语替换成通俗比喻"
```

## 5. 常见场景模板

### 5.1 编程开发

```markdown
【角色】你是一名精通 [语言/框架] 的高级开发工程师。
【背景】我的项目环境是 [环境信息]，当前项目结构如下：
[目录结构或核心代码]
【需求】我需要实现 [具体功能描述]。
【约束】
1. 不要修改现有 API 接口
2. 遵循 [命名规范/代码风格]
3. 只输出修改的部分，不要重写整个文件
【输出格式】请给出修改后的完整代码，并用注释标注改动位置。
```

### 5.2 网页样式调整

```markdown
【背景】我有一个 [网页名称] 页面，当前样式见下方代码。
【需求】[按钮/表单/布局] 太单调，需要美化。
【设计方向】使用 [配色方案/风格]。
【参考】（可选）参考 Apple 官网的卡片风格。
【现有代码】```html [粘贴代码] ```
【输出】给出修改后的完整 HTML 文件。
```

### 5.3 Bug 调试

```markdown
【背景】在 [环境] 下运行 [程序名称]。
【错误信息】```
[粘贴完整报错日志]
```
【已尝试】我已经确认了 [排查步骤]，但问题仍然存在。
【相关代码】```python [粘贴核心代码] ```
```

### 5.4 文档总结

```markdown
请阅读以下内容，用 3 个要点总结核心信息：
[粘贴内容]
要求：每条不超过 50 字，用中文。
```

### 5.5 文件定位

```markdown
【背景】我在修改项目中的 [文件名]，需要在 [文件] 中找到 [功能] 相关代码。
【需求】告诉我 [具体代码/函数] 在第几行，以及应该怎么修改。
【代码】```粘贴代码 ```
```

## 6. 避坑指南

### 6.1 常见错误及改进

| 常见错误 | 问题 | 改进方法 |
|----------|------|----------|
| “帮我写个东西” | 目标模糊 | **明确说清要做什么、用于什么场景** |
| “它不工作了” | 缺乏上下文 | **提供错误信息、环境、已尝试的方案** |
| 一次塞入整个项目代码 | 超出处理能力 | **只贴相关部分，用注释说明省略内容** |
| 不给错误日志 | AI 无法诊断 | **完整粘贴报错信息，包括行号** |
| 无格式要求 | 输出可能混乱 | **指定输出格式（表格/JSON/代码块）** |

### 6.2 高效对话 Checklist

- [ ] 我说清楚了我的目标吗？
- [ ] 我提供了必要的背景信息吗？
- [ ] 我指定了输出格式吗？
- [ ] 如果有错误，我附上了完整日志吗？
- [ ] 我拆分了复杂问题吗？

1. [约束1]
2. [约束2]
输出格式：[代码块/文件/修改位置说明]
```

### 7.2 Bug修复万能模板

```
我在 [环境] 运行 [程序/命令]，遇到以下错误：
```[粘贴完整报错日志]```
已排查：[已尝试的解决方案]
相关代码：```[语言] [粘贴代码] ```
```

### 7.3 网页/UI调整万能模板

```
我有一个 [页面名称]，需要调整 [元素/样式]。

期望效果：[描述/参考图]
设计要求：[配色/风格/响应式需求]
输出：修改后的完整代码
```

### 7.4 学习答疑万能模板

```
请用 [初级/中级/专家] 水平解释 [概念]。
要求：
1. 先给一句话总结
2. 再用一个生活中的比喻
3. 最后给一个代码示例
```

### 7.5 文件内容定位万能模板

```
【文件列表】
```[粘贴文件列表]```

【约束】不要修改其他文件的逻辑。
【当前代码】```[粘贴代码] ```
【输出】请给出修改后的完整文件内容。
```

## 8. 后续自定义与扩展

### 8.1 如何添加新场景模板

1. 复制最接近的现有模板
2. 修改标题和内容
3. 保留【角色】【背景】【需求】【约束】框架
4. 在模板末尾添加具体示例

### 8.2 个性化建议

- **高频场景**：将你最常用的 3-5 个模板固定在文档首页
- **项目专属**：为每个长期项目创建独立的提示词模板文件
- **迭代记录**：记录每次成功对话的提示词，积累个人词库

### 8.3 模板命名规范

```
场景_复杂度_版本.md

示例：
编程_Python调试_v2.md
网页_表单美化_v1.md
```

---

> 📌 **最后提醒**：好的提示词是**迭代出来**的，不是一次性写完美的。先用简单描述开始，根据 AI 的回复不断补充和修正，就能得到理想的结果。
