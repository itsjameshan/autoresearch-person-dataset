## 1. 核心原则

### 1.1 AI 对话底层逻辑
- **AI 是「无状态推理器」**：每次对话独立理解当前输入，不记得你之前的“默认设置”。
- **输出质量 = 输入质量 × 模型能力**：模糊的问题 → 模糊的答案；精确的指令 → 精确的输出。
- **隐式约束需显式说明**：AI 不会自动知道你想要的格式、风格、长度或隐藏条件。

### 1.2 高效提问三要素
| 要素 | 说明 | 示例 |
|------|------|------|
| **目标明确** | 说清楚你想解决什么问题、达到什么效果 | “帮我写一个 Python 函数，裁剪图片为 1280×1280 的小块” |
| **背景完整** | 提供现状、已有条件、限制因素 | “图片都放在 D:\images，输出要保存到同级‘裁剪后的小图’文件夹” |
| **约束具体** | 格式、长度、风格、不做什么 | “不要生成 ZIP 下载，直接保存到服务器固定目录，用时间戳命名” |

## 2. 提示词基础框架

```
# 角色
你是一位 [专业领域] 专家，擅长 [具体能力]。

# 背景
我正在做 [项目/任务]，当前遇到的问题是：[描述现状]。
已有信息/文件：[列举关键材料]。

# 需求
请帮我实现以下功能/解决以下问题：
1. [子需求一]
2. [子需求二]

# 约束
- 输出格式：[Markdown 表格 / 代码块 / 纯文本]
- 不要：[生成压缩包 / 使用临时目录 / 覆盖原有文件]
- 风格：[简洁 / 详细 / 带注释 / 分步骤]

# 参考示例（可选）
[提供一个你期望的输出样例，或类似问题的回答结构]
```

### 示例套用（来自本对话）

```
# 角色
后端开发专家，熟悉 Flask、文件处理、ONNX 模型部署。

# 背景
我在写体育场人群检测系统，裁剪页面需要将原始大图切成小图。
当前代码用临时目录 + ZIP 下载，但用户要求直接保存到固定目录。

# 需求
修改 /api/upload_and_crop 接口：
1. 输出目录改为 D:\pythonProject\person_dataset\裁剪结果_{时间戳}
2. 返回 JSON 格式的结果（包含输出路径），不再返回 ZIP 文件流
3. 检测页面能自动接收该路径

# 约束
- 不改变前端自动跳转逻辑
- 保持原有裁剪参数（tile_size, overlap, filter_empty）

# 输出格式
给出完整的 app_win.py 修改代码段。
```

## 3. 结构化提问技巧

### 3.1 拆分复杂问题
- **错误示范**：“帮我做个完整的体育场检测系统”
- **正确拆解**：
  1. 先请 AI 设计模块架构
  2. 再分步骤实现：裁剪 → 检测 → 重建
  3. 每个步骤单独提问，逐步迭代

### 3.2 限定范围，避免发散
- 加前缀：“**只修改** /api/upload_and_crop 这一个函数”
- 加后缀：“**不需要重写整个文件**”
- 用否定：“**不要生成 ZIP 下载**”

### 3.3 指定输出格式
- “用 Markdown 表格列出修改前后的对比”
- “给出可直接复制的 Python 代码块”
- “按步骤编号说明操作流程”

### 3.4 设定身份，提升专业度
- “你是一位 **Flask 性能优化专家**”
- “你是有 10 年经验的 **前端架构师**”
- 身份能引导 AI 使用更专业的术语和最佳实践

## 4. 优化迭代技巧

### 4.1 追问修正
| 情况 | 策略 |
|------|------|
| 理解偏离 | “你误解了我的意思，我的需求是……” |
| 缺少细节 | “请补充代码中的注释” |
| 输出太短 | “请详细解释每一步” |
| 输出冗余 | “精简到核心逻辑，不要解释性文字” |

### 4.2 补充上下文
- 当 AI 不知道你之前的对话时，主动粘贴关键信息（如之前的代码、错误日志）。
- 使用格式：`以下是当前的代码：```python ... ````

### 4.3 分段输出控制
- “先给出架构图，再输出代码”
- “先分析问题原因，再给出解决方案”
- “分三步回答：1. 原理 2. 代码 3. 测试用例”

### 4.4 精简/扩写控制
- 扩写：“请展开说明为什么选择这个方案，列出优缺点”
- 精简：“用一句话总结核心思路，然后只给代码”

## 5. 常见场景模板

### 5.1 编程开发
```
你是一位资深 Python 开发。
现有代码：[粘贴代码]
运行时报错：[粘贴错误信息]
请定位问题并给出修复后的完整函数。
要求：保持原接口不变，添加必要的异常处理。
```

### 5.2 文案写作
```
请根据以下要点写一篇产品介绍：
- 目标用户：数据科学初学者
- 核心功能：一键安装 Python 环境
- 语气：轻松、鼓励，避免术语堆砌
输出格式：三段式（痛点 → 解决方案 → 行动号召）
```

### 5.3 学习答疑
```
我正在学习 [概念/技术]，目前理解了 [已有认知]，但对 [具体难点] 感到困惑。
请用生活化比喻解释，然后给一个最小代码示例，最后提供 3 个自测题。
```

### 5.4 数据分析
```
给你一个 DataFrame，列名：date, product, sales。
请完成：
1. 按 product 分组，计算每月销售总额
2. 找出每个产品销售额最高的月份
请输出代码 + 结果示例。
约束：使用 pandas，代码要有注释。
```

### 5.5 文档总结
```
请总结以下文档的核心知识点，分条列出，每条不超过 50 字。
原文：[粘贴长文本]
额外要求：保留重要数字、步骤、结论。
```

## 6. 避坑指南

### 常见错误及修正

| 错误提问 | 问题分析 | 正确提问 |
|----------|----------|----------|
| “这段代码报错了，帮我看看” | 缺少错误信息 | “运行以下代码出现 `NameError`，请修复” + 代码+完整报错 |
| “怎么实现裁剪功能？” | 过于宽泛 | “Python 中如何用 OpenCV 将大图滑动切成 1280×1280 并有 200 像素重叠？” |
| “输出结果不对” | 未描述预期与实际 | “期望输出是 `['apple','banana']`，实际得到 `['apple']`，请修正” |
| “帮我优化一下” | 未指定优化目标 | “请优化以下 SQL 查询，目标是减少执行时间，索引已有 `(created_at)`” |

### 其他高频坑
- ❌ **让 AI 猜测路径**：不说“保存在用户目录”，要说“保存在 `D:\data\output`”
- ❌ **忽略格式约束**：不指定输出格式 → AI 可能自由发挥，增加后期处理成本
- ❌ **一次性提太多需求**：超过 5 个并列需求时，AI 容易遗漏，建议分 2-3 次提问

```markdown
[你希望 AI 扮演的身份]

[一句话清晰说明要完成的核心任务]

# 输入材料
[粘贴代码、文本、数据、错误日志等]

# 具体要求
- 输出格式：[JSON / Markdown / 表格 / 带行号的代码块]
- 风格：[详细注释 / 简洁 / 分步骤]
- 必须包含：[关键字段、关键步骤、关键数字]
- 禁止包含：[敏感词、无关内容、宏定义等]

# 附加约束
- 不要额外解释原理（除非我要求）
- 不要增加我未提及的功能
- 保持原有接口签名不变

# 参考样例（可选）
[提供一个你最满意的输出样式]
```

## 8. 后续维护与扩展

- **定制自己的模板库**：将高频使用的提示词保存为本地 `.md` 文件，分类管理（例如 `coding.md`、`writing.md`）。
- **记录有效技巧**：当某个提问方式特别有效时，及时补充到本文档“结构化提问技巧”章节。
- **更新约束清单**：随着 AI 模型迭代，某些旧技巧可能失效，定期测试并调整。
- **分享与迭代**：与同事/朋友交换提示词模板，互相打磨，形成团队最佳实践。
