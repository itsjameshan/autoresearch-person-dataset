# 二、核心问题与修复方案（重点复盘）

## 问题1：脚本报错 NameError: name \&\#39;key\&\#39; is not defined

原因：apply\_changes函数中变量名写错（手滑将param写成key），导致变量未定义。

修复：将函数中所有“key”替换为“param”，同时保留用户核心要求（无git回滚、锁定YOLO12s、自动调参）。

## 问题2：训练跑完一轮后无任何解释，直接进入下一轮

原因：脚本默认只打印关键训练信息，指标解析、提升判断逻辑后台执行，无直观反馈。

修复：在main函数中添加日志打印代码，每轮跑完后显示“本轮指标、当前总分与历史最佳对比、提升判断结果”，让用户清晰了解脚本运行状态。

## 问题3：用户误将打印代码插入错误位置，导致报错

原因：用户将新增的打印代码插入到m、current\_score等变量定义之前，导致变量未定义报错。

修复：明确打印代码的正确位置（在m = parse\_metrics\(\)之后、log\_experiment\_result之前），并提供完整可直接替换的main函数，避免用户插错位置。

## 问题4：训练多轮后，results\.tsv表格为空

原因：log\_experiment\_result（表格写入函数）位置错误，仅在训练有提升时可能执行，无提升时不写入，导致表格空白。

修复：将log\_experiment\_result函数移至判断逻辑之外，确保“无论训练是否有提升、是否失败，每轮都写入表格”，避免表格空白。

## 问题5：表格中所有指标数据均为0\.0000

原因：parse\_metrics（指标解析函数）的正则表达式，与用户训练日志的指标格式不匹配，无法解析到真实指标（用户日志指标为“all  857  20916  0\.492  0\.572  0\.475  0\.136”格式，原正则匹配“cds: x\.xxx”格式）。

修复：修改parse\_metrics函数，使用适配用户日志格式的正则表达式，精准匹配“all”开头的指标汇总行，同时用mAP50代替cds（用户日志无cds指标），确保解析到真实的Precision、Recall、mAP50指标。

## 问题6：用户疑问“是否需要结束训练重新开”

结论：无需急着重开，当前轮次跑完后，新修复的代码会自动生效；若想立刻生效，按Ctrl\+C停止脚本后重新运行即可，避免浪费已消耗的算力。
